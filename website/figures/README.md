# Numra figures

Reproducible chart pipeline for the Numra web presence.

Every plot shipped to `numra-rs.org`, `book.numra-rs.org`, or
`examples.numra-rs.org` is generated by a Python script in this directory.
The pipeline enforces SPEC §5.2 evidence rules: every figure carries the
commit SHA, hardware, compiler, problem statement, and a link to the
script that reproduces it.

## Why Python?

- **Mathematical typesetting.** matplotlib's built-in mathtext (Computer
  Modern) renders math competently without a TeX Live install. Escalate
  to `text.usetex=True` only on a per-figure basis if needed.
- **Reproducibility.** Single source of truth for the visual style
  (Wong color-blind-safe palette matching `tokens.css`).
- **Provenance.** Captions and sidecar `.provenance.txt` files record
  the exact toolchain and hardware at render time.

## Setup

```bash
cd website/figures
uv sync             # install matplotlib, numpy, pandas, scipy
make smoke          # render the smoke-test SVG to verify the pipeline
```

`uv` is required (Homebrew: `brew install uv`). The Makefile assumes
`uv run` is on `PATH`.

## Layout

```
figures/
├── pyproject.toml       # uv-managed dependencies
├── Makefile             # one rule per output category
├── smoke_test.py        # trivial pipeline check
├── lib/
│   ├── style.py         # Wong palette, mathtext='cm', serif body
│   ├── captioning.py    # provenance metadata + caption stamp
│   └── data.py          # criterion estimates.json → DataFrame
├── home/                # home-page evidence (Phase 1)
├── og/                  # OG default + apple-touch-icon
├── perf/                # performance chapter (Phase 2)
├── comparisons/         # numra vs scipy charts (Phase 2)
└── examples/            # examples-gallery thumbnails (Phase 2)
```

## Output destinations

The Makefile routes outputs to the right Astro public dir:

| Source               | Output                                  |
| -------------------- | --------------------------------------- |
| `home/*.py`          | `website/site/public/figures/`          |
| `og/*.py`            | `website/site/public/og/`               |
| `perf/*.py`          | `website/book/src/assets/figures/`      |
| `comparisons/*.py`   | `website/book/src/assets/figures/`      |
| `examples/*.py`      | `website/examples/public/thumbs/`       |

Each script writes both a `<name>.svg` and a sibling
`<name>.svg.provenance.txt` with the full hardware/toolchain fingerprint.
Both are checked into git so future readers can audit a figure without
re-running the script.

## Adding a new figure

1. Create `<category>/<name>.py` (use `smoke_test.py` as the template).
2. At the top, do:
   ```python
   from lib import style
   from lib.captioning import Provenance, save_with_provenance
   import matplotlib.pyplot as plt
   style.apply()
   ```
3. Build the plot, then call `save_with_provenance(fig, output_path, prov)`.
4. `make <category>` to render. Check the output SVG and sidecar `.txt`.

## Refreshing benchmark data

Figures in `perf/` and the home-page hero chart consume Criterion output
from `numra-bench/`. The flow:

```bash
cd ../..
cargo bench -p numra-bench -- bench_tolerance_scaling
# → Criterion writes target/criterion/<group>/<bench>/new/estimates.json

cd website/figures
make home   # re-renders the hero chart with updated timing
```

`lib/data.py` parses Criterion's `estimates.json` files into a flat
DataFrame. Don't commit `target/` — only the rendered SVGs go to git.

## Style invariants

- **Palette.** Wong (color-blind safe). Series colors must match the
  `--plot-1..8` tokens in `website/site/src/styles/tokens.css`. Don't
  introduce a second palette.
- **Math.** mathtext (`fontset='cm'`). Inline `$...$`, display `$$...$$`.
- **Captions.** Always go through `save_with_provenance()`. Never ship
  a figure that doesn't declare problem, solver, tolerance, hardware,
  rustc version, Numra commit SHA, and a repro-script path.
- **No bitmaps for plots.** SVG only. PNG is fine for OG images and
  apple-touch-icons (rasterized at the source).
